# 마이페이지 인계 사항

## 구성과 연결

- `MyPageDashboard.jsx`: 데이터, 프로필, 자기소개, 최근 활동, 주문, 리뷰, 친구 목록, 편집 다이얼로그.
- `assets/`: 마이페이지 전용 이미지·아이콘 26개. 컴포넌트의 상대 URL을 통해 Vite 빌드에 포함됩니다.
- `mypage.css`: 마이페이지 스타일. 상위 레이아웃 보정은 `:has(.mypage-dashboard)` 조건으로 마이페이지에서만 적용됩니다.
- 기본 export: `MyPageDashboard`.
- 기존 props: `activityItems`, `friendItems`, `orderItems`, `reviewItems`. 생략하면 Figma 미리보기 데이터를 표시합니다.
- 닉네임과 자기소개는 `nintendo-mypage-profile` localStorage 항목에 저장됩니다. 실제 계정 API는 연결하지 않았습니다.

마이페이지 전용 JSX, CSS, 데이터, 이미지·아이콘, 인계 문서는 이 폴더 안에 모여 있습니다. 기존 `public/images/mypage/`의 이미지 26개는 `assets/`로 이동했습니다. 담당 범위 밖에 남아 있는 `src/pages/mypage/MyPage.jsx`의 연결 변경은 팀장이 함께 반영해야 합니다. `package-lock.json`에도 별도의 기존 변경이 남아 있습니다.

## 확인 방법

`npm run dev -- --host 127.0.0.1 --port 4174` 실행 후 `http://127.0.0.1:4174/mypage`에 접속합니다.

- 닉네임·자기소개 저장 및 새로고침 후 유지
- 잘못된 형식의 프로필 저장 데이터에 대한 기본값 처리
- 온라인 상태 선택, 설정, 주문·활동 더보기, 친구 목록, Escape로 다이얼로그 닫기
- 이미지 로딩, 데스크톱 1280·1440·1920px 가로 넘침 여부
- 공통 푸터의 위 마진 40px, 데스크톱 내부 위 패딩 121px 유지 및 여백 배경 #ededed

위 동작과 담당 폴더 ESLint·공백 검사는 통과했습니다. 별도의 필터 UI는 없습니다. 모바일 390px에서는 가로 넘침이 있으며, 요청된 데스크톱 전용 범위에 따라 모바일 스타일은 추가하지 않았습니다.

## 빌드 관련 확인 사항

현재 Windows / Node 24.11.1 환경에서 기본 빌드는 기존 출력 폴더를 비우는 과정에서 프로세스 종료 코드 `0xC0000409`로 종료됩니다. 네이티브 프로세스 종료의 상세 원인은 아직 확인되지 않았습니다.

- 동일 설정의 메모리 빌드(`write: false`): 통과
- 새로운 임시 출력 경로를 지정한 `npm run build -- --outDir <새 임시 경로>`: 통과
- 기본 dist에 출력하되 `emptyOutDir: false`로 실행한 진단 빌드: 통과
- ASCII·한글 임시 경로에 대한 최소 Rolldown 출력 검사: 모두 통과

따라서 출력 폴더 정리 단계가 의심되며, 소스 컴파일이나 한글 경로만의 문제로 확인된 것은 아닙니다. `emptyOutDir: false`는 오래된 산출물을 남길 수 있어 공통 설정에 영구 적용하지 않았습니다. 팀장이 공통 빌드 실행 환경을 점검해야 합니다.

2026-09-28 fetch 기준 `origin/main`의 `7e675be` 변경은 홈 화면 영역이며 마이페이지 작업 경로와 겹치지 않았습니다. 실제 병합 및 병합 후 통합 테스트는 수행하지 않았습니다.
